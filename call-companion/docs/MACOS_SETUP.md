# Настройка MacBook Air M1

Всё ниже писалось без доступа к вашему Mac. Шаги с пометкой «не проверено на устройстве» по документации API; если что-то не заведётся, пришлите вывод `callc doctor` и текст ошибки.

## 1. Установка

```bash
brew install python@3.12 uv                       # если ещё нет
git clone -b claude/smart-call-companion-4icjl5 https://github.com/dansichka/start
cd start/call-companion
uv venv && source .venv/bin/activate
uv pip install -e ".[mac]"                        # mlx-whisper, sounddevice, pywebview
mkdir -p ~/.config/callcompanion && cp examples/config.example.toml ~/.config/callcompanion/config.toml
```

Откройте конфиг и впишите свои `name` и `aliases`: по ним компаньон понимает, что вопрос адресован вам. Доступ к Claude: `export ANTHROPIC_API_KEY=...` (можно добавить в `~/.zshrc`) или `ant auth login`.

## 2. Системный звук

Компаньону нужен звук собеседников отдельно от вашего микрофона. Есть два пути.

**Путь A. BlackHole (проще, ставится за минуту).**

1. `brew install blackhole-2ch`
2. «Настройка Audio MIDI» → «+» → «Создать устройство с несколькими выходами». Отметьте **BlackHole 2ch** и ваши наушники или динамики, включите «Коррекция дрейфа» для не главного устройства.
3. Выберите это устройство выходом системы (или в настройках динамика самого приложения для звонков).
4. Микрофон остаётся настоящим. В конфиге уже стоит `system_device = "BlackHole 2ch"`.

Громкость у устройства с несколькими выходами недоступна: регулируйте её на самих наушниках или в приложении звонка. Слушайте звонок **в наушниках**: через динамики голос собеседника попадает в микрофон и реплики дублируются.

**Путь B. Нативный помощник `audiotap` (без BlackHole, не проверено на устройстве, не компилировался).**

```bash
cd native/macos/AudioTap
swift build -c release
mkdir -p ~/.callcompanion/bin && cp .build/release/audiotap ~/.callcompanion/bin/
```

В конфиге `capture.backend = "audiotap"`. Он берёт системный звук через ScreenCaptureKit, нужен macOS 13+ и разрешение «Запись экрана и системного звука» для приложения, из которого вы запускаете `callc` (Terminal, iTerm).

## 3. Разрешения macOS

«Системные настройки → Конфиденциальность и безопасность»:

| Разрешение | Кому | Зачем |
|---|---|---|
| Микрофон | Terminal / iTerm (или IDE, откуда запускаете) | ваша речь |
| Запись экрана и системного звука | то же приложение | только для пути B |

После выдачи разрешения перезапустите терминал. Универсального доступа (Accessibility) сейчас не требуется.

## 4. Проверка

```bash
callc doctor
```

Проверяет Python, платформу, ключ Claude, конфиг, ваше имя, папку данных (права 700), журнал, kernel (доступность, возраст пакета), распознавание (установлен ли `mlx-whisper`, скачана ли модель), звук (есть ли BlackHole или `audiotap`), порт HUD и ресурсы. У каждого пункта, который не в порядке, есть строка «→ что делать».

Первый запуск скачивает модель распознавания (около 1,6 ГБ для `large-v3-turbo`), поэтому первый раз запустите заранее, до звонка.

## 5. Производительность на M1 Air

У Air нет вентилятора, и под нагрузкой он замедляется. Что с этим делать:

- **Модель по объёму памяти.** На 8 ГБ рядом с видеозвонком тесно: `asr.model = "mlx-community/whisper-small-mlx"`. На 16 ГБ подойдёт `large-v3-turbo` (по умолчанию). `callc doctor` предупредит.
- **Режим `on_hesitation`** (по умолчанию) вызывает модель в разы реже, чем `always`.
- **Задержка подсказки.** Для самых быстрых ответов поставьте `llm.model = "claude-haiku-4-5"`: быстрее и дешевле, но слабее.
- **Питание и вкладки.** Работайте от сети, закройте тяжёлые приложения. Распознавание идёт одним потоком, чтобы не греть корпус.
- Реальную задержку покажет поле «latency» в HUD (наведите на статус).

## 6. HUD: где смотреть подсказки

| Способ | Команда | Замечание |
|---|---|---|
| Вкладка браузера | `callc run … --open` | проще всего; вкладка видна, если делитесь всем экраном |
| Плавающее окно | `callc run … --window` | не проверено на устройстве: окно поверх остальных; просит macOS не показывать его в шаринге экрана, но это пожелание, а не гарантия |
| **Телефон или планшет** | `ui.host = "<адрес Mac в Tailscale>"`, откройте напечатанную ссылку | самый надёжный: экран устройства не попадает ни в шаринг, ни в запись |

Ссылка содержит одноразовый токен и отдаёт cookie; без неё HUD ничего не показывает. Если открываете HUD по имени хоста, добавьте его в `ui.allowed_hosts` (адреса по IP разрешены всегда).

Не показывайте весь экран, пока открыт HUD: делитесь окном или приложением.

## 7. kernel

Нужен один из способов (или оба вместе):

- **Файл-пакет** `~/.callcompanion/pack.jsonl`, который kernel выгружает и синхронизирует на Mac. Работает при выключенном ПК.
- **Сеть**: поставьте Tailscale на оба компьютера, в конфиге `kernel.http.base_url = "http://<адрес ПК>:8765"`, токен в переменной `KERNEL_COMPANION_TOKEN`. На ПК откройте порт только на интерфейсе Tailscale.

Как подключить настоящий kernel: [KERNEL_CONTRACT.md](KERNEL_CONTRACT.md). Пока он не подключён, проверить связь можно на демо-данных командой `callc demo-kernel`.

## 8. Если что-то не работает

| Симптом | Вероятная причина | Что сделать |
|---|---|---|
| Не слышно собеседников | выход системы не Multi-Output с BlackHole | пункт 2, проверьте, что звук идёт и в наушники, и в BlackHole |
| Реплики дублируются | звук идёт через динамики в микрофон | наушники |
| `нет доступа к микрофону` | нет разрешения для терминала | пункт 3, перезапустите терминал |
| Подсказки запаздывают | тяжёлая модель распознавания или модель ответов | пункт 5 |
| `kernel не ответил вовремя` | ПК выключен, Tailscale не поднят, токен неверный | `callc doctor` покажет причину; работа продолжится по пакету |
| HUD не открывается на телефоне | не тот `ui.host`, имя не в `allowed_hosts`, нет токена в ссылке | откройте ссылку, напечатанную при запуске |
| Много лишних подсказок | слишком чувствительные настройки | `live.max_whispers_per_min`, `live.min_gap_s`, `assist = "manual"` |
